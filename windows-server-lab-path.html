Windows Server Lab Path

Build a Windows Server environment on your own hardware or campus lab computers. Use the same virtual machines from setup through file access testing. You’ll need access to a hypervisor and Windows installation media.

Check off the results you observe in your VMs. Progress is saved in this browser when storage is available.

  2. Build the Active Directory domain

Lab 1 · Build the virtual lab

Required setup

A virtualization-capable computer with enough RAM and disk to run three VMs. Obtain licensed or evaluation Windows Server installation media and Windows 11 Pro or Enterprise media. You build and run all VMs on your own computer or in a campus lab.

Build steps

  1. Enable hardware virtualization and install your hypervisor. Create a private virtual switch (or the equivalent VM-only network). Connect all three VMs to that switch. Use the VM consoles for management.
  2. Install Windows Server with Desktop Experience on SA-DC1 and SA-FS1. Install Windows 11 Pro or Enterprise on SA-CL1. Set each computer name and restart.
  3. Assign IPv4 addresses 192.168.77.10 to SA-DC1, 192.168.77.20 to SA-FS1, and 192.168.77.30 to SA-CL1, each with prefix length 24. Leave the default gateway blank. Choose another private subnet if it conflicts with your lab and update the addresses throughout the path.
  4. Run ipconfig /all in the three VM consoles. Check the intended adapter, address, and prefix. In the hypervisor, confirm each VM is attached to the same private switch and has no other active network adapter.
Verify in your VMs

Evidence and what to keep

Keep the three VMs, the switch, and a record of computer names and addresses.

Next lab · Build the Active Directory domain

Lab 2 · Build the Active Directory domain

Required setup

Complete Lab 1 · Build the virtual lab and use the environment it produces.

Use the three running VMs from Lab 1. Confirm the addresses and switch attachments before starting.

Build steps

  1. On SA-DC1, add the Active Directory Domain Services role in Server Manager. Promote the server using Add a new forest and the root domain ad.academy.test. Include DNS, record the suggested NetBIOS name (AD), set a DSRM password, and reboot.
  2. Set SA-DC1’s preferred DNS to its own address. On SA-FS1 and SA-CL1 set preferred DNS to 192.168.77.10. Use only the internal DNS server for this lab.
  3. On both member machines, run Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.ad.academy.test. If it fails, check the adapter’s DNS address, the virtual switch, and the DNS role on SA-DC1.
  4. Using the computer’s System Properties, join SA-FS1 and SA-CL1 to ad.academy.test with authorized domain credentials. Reboot both, then run (Get-CimInstance Win32_ComputerSystem).Domain on each.
Verify in your VMs

Evidence and what to keep

Keep the domain controller, DNS settings, and both domain members. Record successful lookup and join results.

Next lab · Create department users and groups

Lab 3 · Create department users and groups

Required setup

Complete Lab 2 · Build the Active Directory domain and use the environment it produces.

Use the working domain and joined client from Lab 2. Confirm SA-CL1 can discover the domain controller.

Build steps

  1. In Active Directory Users and Computers, create an OU named Departments and a child OU named Finance. Create a global security group named GG-Finance in Finance.
  2. Create two standard test accounts, finance.test and outsider.test. Add finance.test to GG-Finance. Leave outsider.test outside GG-Finance. Confirm neither account is an administrator.
  3. Create a domain-local security group called DL-Finance-Modify and add GG-Finance to it. Use this resource group for permissions in the next lab.
  4. On SA-CL1, sign in as each domain user in a separate session. Run whoami /groups to verify that finance.test has the expected finance group membership and outsider.test does not. Sign out and back in after membership changes.
Verify in your VMs

Evidence and what to keep

Keep the test accounts, group memberships, and joined workstation for the access tests.

Next lab · Configure and verify a departmental share

Lab 4 · Configure and verify a departmental share

Required setup

Complete Lab 3 · Create department users and groups and use the environment it produces.

Use the same domain, joined file server and client, and two test identities from Labs 1–3. Confirm SA-CL1 resolves SA-FS1 by name and both test accounts can sign in.

Build steps

  1. On SA-FS1, create a fresh C:\LabShares\Finance folder and put a sample file in it. In Advanced Security, review inherited permissions. Preserve SYSTEM and Administrators with Full Control, grant AD\DL-Finance-Modify Modify, and remove broad access entries inherited by this lab folder. Work only on this new folder.
  2. Share the folder as Finance. Grant AD\DL-Finance-Modify Change and Administrators Full Control at the share. Remove the default Everyone share entry if present. Enable the File and Printer Sharing SMB-In firewall rule for the Domain profile if needed.
  3. On SA-CL1, sign in as finance.test. Open \\SA-FS1.ad.academy.test\Finance, read the sample file, and create a new test file. Sign out completely.
  4. Sign in as outsider.test and open the same path. Capture the access-denied result. If both tests fail, verify name resolution and SMB connectivity with Test-NetConnection SA-FS1.ad.academy.test -Port 445 before changing permissions.
Verify in your VMs

Evidence and what to keep

Submit the share and NTFS permissions, both client test results, and a short configuration handoff. Keep the domain for future Academy labs.
